Reasoning needs a way into action

A reasoning model can understand “put the yellow block on the orange one, then add the red block.” The robot policy still needs to know which objects those words refer to, where to move, and when to continue to the next step.

COMPASS is a SceneCode-based bridge system between System 2 and System 1. System 2 interprets the task and writes a structured program. SceneCode carries the objects, goals, steps, and expected outcomes. The bridge grounds these references in the scene and passes execution targets into System 1.

What is SceneCode?

SceneCode is a structured description of the task and the scene that both systems use. It names the objects, records their current states and relations, specifies the next action segment, and states what should be true afterward.

The task program carries the longer-term requirement: for example, the orange block must be below the yellow block, and the red block must finish on top. At each review, System 2 updates the current scene and the commands needed to make progress toward that requirement.

Expected outcomes

What the next observation should establish.

on_top(yellow_block, orange_block)

An object reference includes an image anchor, such as a pixel near the center of the orange block. SAM3 uses that reference to locate the object. Depth and camera geometry lift its location into 3D, giving the controller a target that refers to the current scene.

The complete pipeline

COMPASS carries the task through program construction, scene grounding, target encoding, policy execution, and outcome checking. Each new observation can change the next command while the original task requirement stays explicit.

There are two update rates. System 1 produces action chunks from the current observations and execution target. System 2 reviews the accumulated outcome at selected points and updates SceneCode. This lets the program retain a multi-step plan while responding to changes in the scene.

How the encoder connects the program to actions

The encoder is the learned connection from SceneCode’s grounded execution targets into pi0.5. It receives target geometry, the current robot state and execution phase, together with visual features from the policy. Its output changes the policy’s internal representation before actions are generated.

The default network is an MLP with two hidden layers of width 768, a visual-feature projection, and a 2,048-dimensional output. The resulting vector is added to the language-token residual at PaliGemma layer 10. The target features include the hand-to-target displacement; RoboDojo also supplies the arm state and active-arm information needed for bimanual execution.

Learning the bridge

Training runs the encoder and frozen policy together. The policy predicts an action chunk, and the training objective measures how closely its resulting hand or object position follows the grounded target. Reach and carry terms encourage progress toward the goal; gripper and orientation terms retain the associated manipulation behavior. Release targets add the opening condition.

Gradients pass through pi0.5 to train the encoder. The reasoning model and pi0.5 weights stay frozen. Teacher corrections collected on states encountered during execution can be added as DAgger training data for this bridge.

Planning, correction, and embedding work together

01 / PLAN

Decide what comes next.

Keep the selected objects, subgoals, order, and completion conditions in the same program.

02 / CORRECTION

Redirect execution.

Check what happened, revise the target or plan, and continue. Teacher corrections also supply DAgger training data for the bridge encoder.

03 / EMBEDDING

Give intent a location.

Ground objects with SAM3 and depth. Encode the target, robot state, and policy features into a signal that guides System 1.

The default system uses Sol for reasoning and pi0.5 for robot actions. SceneCode records the plan and checks; perception resolves its object references; the encoder supplies target guidance; and runtime feedback determines which part of the program to execute next.

On RoboDojo ICL, the current run records a task-mean progress score of 17.69 for COMPASS and 15.90 for pi0.5, with 79 versus 65 successful cases.

What SceneCode makes possible

The core of COMPASS is a shared representation that reasoning can write, perception can ground, and the action policy can use. Planning, corrections, and embeddings work through that bridge as the task unfolds.
