推理需要一条通往行动的路

推理模型能听懂“把黄色积木放到橙色积木上，再把红色积木加上去”。但机器人策略还需要知道这些词指的是哪些物体、要移动到哪里、什么时候进入下一步。

COMPASS 是一个基于 SceneCode、连接 System 2 和 System 1 的桥接系统。 System 2 理解任务并写出一个结构化程序。SceneCode 记录物体、目标、步骤和预期结果。桥接部分把这些引用对应到场景中的实际物体，再把执行目标传给 System 1。

SceneCode 是什么？

SceneCode 是对任务和场景的结构化描述，两个系统共用它。 它给物体命名，记录物体当前的状态和相互关系，指定下一段动作要做什么，并写明做完之后应该成立的状态。

任务程序承载长期要求：比如橙色积木必须在黄色积木下面，红色积木最后要在最上面。每次复查时，System 2 都会更新当前场景，以及朝这个要求推进所需的命令。

物体与状态

有什么、在哪里、手里正拿着什么。

orange_block · anchor [325, 254] · held by left gripper
关系

物体之间、物体与机器人之间的关系。

above(yellow_block, orange_block)
命令

下一段动作中应该发生什么。

steer → orange_block · object = yellow_block · release = true
预期结果

下一次观测应该确认什么。

on_top(yellow_block, orange_block)

物体引用包含一个图像锚点，比如橙色积木中心附近的一个像素。SAM3 根据这个引用找到物体，再用深度和相机几何把位置提升到 3D，让控制器拿到一个对应当前场景的目标。

完整流程

COMPASS 让任务依次经过 程序构建、场景定位、目标编码、策略执行和结果检查。每次新的观测都可能改变下一条命令，而原始的任务要求始终明确保留。

系统有两种更新频率。System 1 根据当前观测和执行目标生成动作块；System 2 在选定的时间点复查累积的结果，并更新 SceneCode。这样程序既能保住多步计划，又能对场景变化做出反应。

encoder 如何把程序接到动作上

encoder 是学到的连接，把 SceneCode 中已定位的执行目标送进 pi0.5。它接收目标几何、当前机器人状态和执行阶段，以及来自策略的视觉特征。它的输出会在生成动作之前改变策略的内部表示。

默认网络是一个 MLP，包含 两个宽度为 768 的隐藏层、一个视觉特征投影，以及 2,048 维的输出。得到的向量会加到 PaliGemma 第 10 层的语言 token 残差上。目标特征包括手到目标的位移；RoboDojo 还会提供双臂执行所需的手臂状态和当前活动臂信息。

学习这座桥

训练时 encoder 和冻结的策略一起运行。策略预测一段动作块，训练目标衡量由此得到的手或物体位置与已定位目标的贴合程度。接近和搬运项鼓励向目标推进；夹爪和朝向项保留相应的操作行为。释放目标还会加上张开夹爪的条件。

梯度穿过 pi0.5 来训练 encoder。 推理模型和 pi0.5 的权重保持冻结。 在执行中遇到的状态上收集的教师纠正，可以作为 DAgger 训练数据加入，用来训练这座桥。

规划、纠正和嵌入协同工作

01 / 规划

决定下一步做什么。

把选中的物体、子目标、顺序和完成条件放在同一个程序里。

02 / 纠正

调整执行方向。

检查发生了什么，修改目标或计划，然后继续。教师纠正也为桥接 encoder 提供 DAgger 训练数据。

03 / 嵌入

给意图一个位置。

用 SAM3 和深度定位物体。把目标、机器人状态和策略特征编码成一个引导 System 1 的信号。

默认系统用 Sol 做推理，用 pi0.5 输出机器人动作。SceneCode 记录计划和检查；感知模块解析其中的物体引用；encoder 提供目标引导；运行时反馈决定接下来执行程序的哪一部分。

SceneCode 带来了什么

COMPASS 的核心是一个共享表示：推理可以写它，感知可以定位它，动作策略可以用它。随着任务推进，规划、纠正和嵌入都通过这座桥起作用。
