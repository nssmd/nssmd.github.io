W1 / Q1 · 基线比较不公平，要和其他自我改进系统比

审稿意见
Unfair baselines. RoboRSI keeps learning on the evaluated tasks, while the baselines do not. As a result, the evaluation shows the gain from self-improvement itself, but not RoboRSI's advantage over other RSI systems or approaches.
Q1: If possible, could the authors compare RoboRSI with related robotic RSI systems (e.g., ASPIRE, ENPIRE, or EmbodiSkill), or with a simple RSI variant built on one of the baselines?
建议回复

We thank the reviewer for this important point and agree that the original comparison measures what self-improvement adds over fixed agents, not RoboRSI's advantage over other self-improving designs. We added three self-improving baselines, all with the same backbone (GPT-5.6-SOL), tool interface, per-episode interaction budget, task panels, and simulator verdict as in Table 1:

(1) ASPIRE (Lu et al., 2026), the closest self-improving code agent, using its released code. Because ASPIRE learns each task with a parallel population search, we report it in two settings: its native protocol with a learning-token budget matched to RoboRSI's total learning cost on the same panel, and a serial adaptation in which each repaired program is released to the episodes that follow, the same stream RoboRSI uses.
(2) OpenETA + flat revision: OpenETA augmented with a reflect-and-repair loop that edits the skill code directly from the failure, without TSR attribution.
(3) OpenETA + EmbodiSkill-style reflection: skill-aware reflection (Ju et al., 2026) that distinguishes wrong skill content from execution lapses and updates the skill accordingly.

On LIBERO-PRO, RoboRSI reaches [X]% vs. [X]% (ASPIRE-serial), [X]% (ASPIRE-native, matched budget), [X]% and [X]% for the two OpenETA variants (new Table [X]). We further separate learning from evaluation (learn-then-freeze, new Table [X]): each method learns on a training split, its library is frozen, and it is evaluated on held-out tasks and on LIBERO-Plus. RoboRSI achieves [X]% vs. [X]% for the best self-improving baseline.

ENPIRE (Xiao et al., 2026) improves neural policies and their training code through physical reinforcement learning on a robot fleet, rather than reusable code skills, so it does not admit a matched comparison in our protocol; we discuss this in Section 2 and note that RoboRSI's execution data can train such policies (Section 4.5.5).

  • 从 LIBERO-PRO 和 RoboTwin 的失败记录里抽至少 20 个失败任务，按失败类别（抓取、放置、运动、过早完成、预算耗尽）分层抽样；预先写好抽样规则，不要事后挑选。
  • 两个条件从相同代码、相同失败轨迹出发，用相同的 Planner、Engineer、Reviewer、Manager 和发布标准；唯一区别是 TSR 先建责任树、定位最早失败节点，flat 直接根据失败提出修改。
  • 每个条件每个任务生成 3 个独立候选（不同采样种子），统计稳定性。
  • 发布标准不变（2 个开发种子成功）；另外在 3 个没参与开发的初始状态上评测。
指标
发布率、未参与开发的初始状态上的成功率、改动的文件数和行数、改动范围是否落在失败分支内、对其他已通过任务的回归率、到发布为止的轮数和 token。
